# REVIEW

## VERDICT

PASS after fixes. The expert draft of RI #3 (Cross-Chain Stablecoin Payment
Orchestration) is structurally complete, correctly leads with Canton's privacy
model, and properly flags the planned/external components — but, like the prior
drafts, shipped with fabricated API identifiers, hallucinated external
citations, footnote noise, no source-grounding, and one inaccurate Canton
factual claim. All blocking issues are corrected in the persisted report
[`docs/ri-reports/03-cross-chain-stablecoin.md`](../ri-reports/03-cross-chain-stablecoin.md),
which carries the Cross-Synchronizer section (§8), house conventions, and the
grant-alignment banner.

Reference-design document; not an M1/M4 acceptance, conformance, audit, or
production-readiness judgment.

## BUGS

Fabricated / inaccurate identifiers (verified against real source 2026-06-24):

- **`AllocationFactory_Allocate`** — no such interface/choice. Real path:
  `SettlementFactory_CreateAllocationInstruction` → `AllocationInstruction_Accept`
  → `Allocation` (requests via `SettlementFactory_CreateAllocationRequest`).
  *Fixed* in prose, code, and diagrams.
- **`BurnerCapability_Seize`** — `BurnerCapability` is a template with **no
  choices**. Seizure runs on the `Allocation`
  (`Allocation_MarkD2InFlightSeizure` → `Allocation_SweepD2InFlightSeizure`) or
  on a holding (`LockedSimpleHolding_ForcedBurn`), gated by `BurnerCapability`.
  *Fixed:* §3 D2 + §4.3.
- **`LockedSimpleHolding_ForceTransfer`** — not a real choice. Real choices:
  `LockedSimpleHolding_Unlock`, `LockedSimpleHolding_ForcedBurn`. *Fixed.*
- **`D2SeizureHook` as a template with `SeizureHook_Sweep`** — `D2SeizureHook`
  is a spine **data record** (`seizureCaseRef`, `custodianDestination`,
  `inFlightHandlingStatus`). *Fixed:* §4.3 uses the real mechanism, no bespoke
  template.
- **`KycClaim` / `TrustedIssuerRegistry` imported from a ZkCredentialGateway
  module** — they are `canton-specs` identity-hook **Shape-B** types. `KycClaim`
  field is `subjectParty` (draft used `.subject`). *Fixed:* attribution + field
  corrected, explicit note added.
- **Module-path errors** — `OpenZeppelin.Experimental.AccessControl.*` →
  `OpenZeppelin.AccessControl`; `SimpleHolding`/`TransferPreapproval` live in
  `canton-token-template` `SimpleToken.{Holding,Preapproval}`, not a
  `Splice.Wallet.*` / `OpenZeppelin.Experimental.Token.*` path. *Fixed.*
- **`SettleBatch with extraTransferLegSides=`** — `extraTransferLegSides` is an
  `Allocation_Settle` field; the batch path uses `allocations`/`requests`.
  *Fixed* to match the spine shape used across the RIs.

Confirmed-correct (kept): `OpenZeppelin.Experimental.Settlement.Cip112`,
`SettlementFactory_SettleBatch`, `SettlementFactory_CreateAllocationInstruction`,
`AllocationInstruction_Accept`, `Allocation`, `BurnerCapability`,
`SimpleHolding`/`LockedSimpleHolding`/`SimpleTokenRules`, `TransferPreapproval`,
`CredentialGatedActionRequest`/`MockVerificationResult`, `nextIterationFunding`,
`RequestedAllocation.committed`.

## ANTI-PATTERNS

- **Inaccurate Canton claim.** The draft asserted a "strict 10-minute open mining
  round cycle" as a **transaction signing timeout** that `TransferPreapproval`
  exists to "circumvent." This conflates Canton Coin minting rounds with
  transaction latency and is not load-bearing. *Fixed:* restated the
  `TransferPreapproval` rationale as delegated accept for offline/cold recipients
  (the real Canton co-authorization requirement), and removed the timeout framing.
- **Footnote-marker noise** (stray trailing digits "spine1", "observers2",
  "cycle13"). *Fixed:* removed; grounded References.
- **Readiness over-claim** ("mathematically verified", production framing).
  *Softened*; no-claims status banner added.
