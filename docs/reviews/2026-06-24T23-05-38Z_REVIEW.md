# REVIEW

## VERDICT

PASS after fixes. The expert draft of RI #4 (Confidential Auction Launchpad) is
the strongest of the four on conceptual grounding — its sealed-bid-via-projection
framing, commit-reveal-as-optional-extension note, and losing-bids-return-to-sender
treatment are correct and well-argued. But, like the prior drafts, it shipped
with fabricated API identifiers, hallucinated external citations (including an
unrelated software-engineering paper), footnote noise, and no source-grounding.
All blocking issues are corrected in the persisted report
[`docs/ri-reports/04-confidential-auction.md`](../ri-reports/04-confidential-auction.md),
which carries the Cross-Synchronizer section (§8), house conventions, and the
grant-alignment banner.

Reference-design document; not an M1/M4 acceptance, conformance, audit, or
production-readiness judgment.

## BUGS

Fabricated / inaccurate identifiers (verified against real source 2026-06-24):

- **`AllocationFactory_Allocate`** — no such interface/choice. Real escrow path:
  `SettlementFactory_CreateAllocationInstruction` → `AllocationInstruction_Accept`
  → committed `Allocation`. *Fixed* in §3 and §5.2.
- **`D2SeizureHook` treated as an invokable hook/template ("the D2SeizureHook is
  invoked")** — it is a spine **data record** (`seizureCaseRef`,
  `custodianDestination`, `inFlightHandlingStatus`). Seizure runs on the
  `Allocation` (`Allocation_MarkD2InFlightSeizure` →
  `Allocation_SweepD2InFlightSeizure`) or holding (`LockedSimpleHolding_ForcedBurn`),
  gated by `BurnerCapability`. *Fixed:* §3.3.
- **`KycClaim` / `TrustedIssuerRegistry` attributed to `zk-credential-gateway`** —
  they are `canton-specs` identity-hook **Shape-B** types. *Fixed:* attribution +
  explicit note.
- **`SettleBatch with instructions = [...]`** — aligned to the real spine shape
  (`allocations = [...]`, `requests = [...]`). *Fixed:* §4.4.
- **`BidRequest_Cancel` returning the allocation cid unchanged** — replaced with
  the real unlock path (`Allocation_Withdraw`) so funds actually return to sender.
- **Module-path nits** — `OpenZeppelin.AccessControl.RoleGrant` /
  `OpenZeppelin.Pausable.PauseState` → `OpenZeppelin.AccessControl` /
  `OpenZeppelin.Pausable`. `AuctionLaunchpad` halt routed through `oz-pausable`
  `PauseState` rather than a mutated local `isPaused` flag. *Fixed.*

Confirmed-correct (kept): `OpenZeppelin.Experimental.Settlement.Cip112`,
`SettlementFactory_SettleBatch`, `Allocation`/`AllocationRequest`/
`AllocationInstruction`, `SettlementReceipt`, `BurnerCapability`,
`SimpleHolding`/`LockedSimpleHolding`/`SimpleTokenRules`, **`Rules_Mint` /
`MintProposal`** (cold-recipient mint), `RoleCapability`,
`CredentialGatedActionRequest`/`MockVerificationResult`/`CredentialRevocationStatus`,
`nextIterationFunding`.

  `srikanth-bitdynamics` GitHub, and (erroneously) an unrelated 2003
  software-engineering workshop paper hosted on mediaTUM. *Fixed:* replaced with
  workspace-grounded References; removal disclosed.
