## VERDICT

PASS — **reject-and-confirm, with two additive items.** The report was already a
freshly-reviewed v1 ([`2026-06-24T22-57-44Z_REVIEW.md`](./2026-06-24T22-57-44Z_REVIEW.md))

## BUGS (fabricated / inaccurate claims in the blueprint — rejected)

- **CIP-86 = "Ethereum JSON-RPC / MetaMask facade"** — mischaracterization.
  `canton-contracts/docs/architecture/cip0086-cip0103-cip0104-m1-acceptance.md`
  defines CIP-0086 as an **ERC-20 middleware & distributed indexer** proposal, not
  a JSON-RPC/ABI facade. It is also out of this RI's scope. The report does **not**
  adopt the facade framing (reject by omission; no edit needed).
- **`AmuletAllocationV2` / `TransferInstructionV2`** — fabricated. Only
  `AllocationV2`, `AllocationRequestV2`, `HoldingV2` exist, and only as upstream
  `Splice.Api.Token.*` imports in `canton-token-template` tests. The RI settles on
  the **local spine** `Allocation` / `AllocationRequest` / `AllocationInstruction`.
- **"Wormhole / LayerZero exist as SVs on the Canton Network"** — unverifiable; no
  workspace grounding. The report keeps the gateway a `[FUTURE]` bounded mock to be
  swapped for a "CCIP/LayerZero-style integration" — appropriately hedged. Reject.
- **`BatchingUtility_MergeHoldings`** — fabricated (an upstream *feature request*,
  not a shipped API). The report's fragmentation mitigation is the spine's
  iterated-settlement change-merge (`nextIterationFunding`), already correct in
  §3/§7.2. Reject.
- **Recurring fabrications already handled by the v1 review** (kept rejected):
  `BurnerCapability_Seize` (no choices on `BurnerCapability`); `D2SeizureHook` as a
  template (it is a data record); `KycClaim` imported from the gateway (it is a
  `canton-specs` identity-hook Shape-B type; field `subjectParty`); the 10-minute
  mining-round "signing timeout" framing.

Confirmed-correct (kept): `OpenZeppelin.Experimental.Settlement.Cip112`,
`SettlementFactory_SettleBatch` / `_CreateAllocationInstruction` /
`_CreateAllocationRequest`, `AllocationInstruction_Accept`, `Allocation`,
`RequestedAllocation.committed`, `nextIterationFunding`, `TransferPreapproval`
(`SimpleToken.Preapproval`, `expiresAt : Optional Time`), `SimpleTokenRules` /
`SimpleHolding` / `LockedSimpleHolding_ForcedBurn`, `D1ComplianceHook` /
`D2SeizureHook` (data records), `KycClaim` / `TrustedIssuerRegistry`.

## GAPS (surfaced by the blueprint — integrated)

- **Expired / unsettled inbound-allocation lifecycle.** Real gap: the local
  CIP-0112 scaffold's `Allocation` has only `Allocation_Settle` + the two D2
  seizure choices — **no cancel/withdraw/reject**. The upstream Token Standard V2
  Allocation lifecycle separates expiry from settlement deadline and adds
  cancel/withdraw/reject (the blueprint's `AmuletAllocationV2`-with-`Cancel` claim,
  stripped of the fabricated name). *Integrated* as a §9 open question
  (`[UPSTREAM]`/`[FUTURE]`), mapped to return-to-sender.
- **Off-ledger reconciliation via V2 transfer-events.** The V2 transfer-events API
  (`Splice.Api.Token.TransferEventsV2`, real upstream import in
  `canton-token-template`) lets a treasury correlate the Canton credit with the
  inbound cross-chain message id. *Integrated* as §7.4 (`[UPSTREAM]`), with explicit
  no-claims hedging (no FDICIA/SOX, no completeness/audit claim).
